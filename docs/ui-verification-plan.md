# 크로뉴스 UI 개선과 검증 계획

아래 프롬프트를 작업 단위로 순서대로 실행한다. 검증 결과에는 화면 너비, 로그인 상태, 실제 또는 모의 응답 여부를 기록한다.

## 1. 화면 디자인과 접근성

> 퀴즈 시작·플레이·결과, 로그인, 랭킹, 계정 메뉴를 360·768·1280px에서 점검하라. 기존 브랜드와 게임 규칙을 유지하면서 공통 글자 크기, 줄 높이, 여백, 버튼 규격을 적용하라. 중복 문구와 불필요하게 중첩된 카드의 배경을 정리하라. 긴 닉네임과 뉴스 제목, 30개 번호판, 긴 결과 창, 키보드 포커스를 확인하라. 가로 넘침, 글자 잘림, 도달할 수 없는 버튼을 재현하면 수정하고 같은 조건에서 재검증하라.

합격 기준은 세 너비에서 가로 넘침이 없고, 긴 결과의 닫기 버튼과 계정 메뉴 항목에 접근할 수 있는 것이다.

## 2. 퀴즈와 계정 동작

> 비회원과 로그인 사용자 흐름을 따로 검증하라. 퀴즈 시작, 일시정지·재개, 힌트 5단계, 교차 글자 입력 및 수정, 제출 실패 후 재시도, 결과 다시 보기, 퍼즐 이동을 확인하라. 계정 메뉴의 바깥 클릭과 Esc, 프로필 편집, 로그아웃 후 화면을 확인하라. 한글 IME는 조합 이벤트 테스트와 실제 키보드 테스트를 구분하라. 운영 랭킹에 테스트 기록을 만들지 않도록 자동화에서는 제출 응답을 모의 처리하라.

합격 기준은 결과 재열기 시 추가 제출이 없고, 일시정지 중 입력이 차단되며, 실제 인증을 검증한 범위가 명시되는 것이다.

## 3. 배포와 운영 확인

> 로컬 확인 이후 배포 단계에서 타입 검사, 단위 테스트, 프로덕션 빌드를 실행하라. 배포 후 홈·로그인·랭킹과 DB 헬스 응답을 확인하라. 한국 시간 기준 오늘 퀴즈 공개 수와 최근 Cron 이력을 읽기 전용으로 검증하라. 예약 설정, 실제 실행, DB 공개 결과를 별개로 기록하고 결과를 확인할 수 없는 항목은 미검증으로 표시하라.

합격 기준은 확인한 배포 커밋, 페이지 응답, 당일 공개 수, 최근 실측 Cron 상태를 함께 보고할 수 있는 것이다.
